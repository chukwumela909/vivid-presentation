# vivid-presentation

A page that is nothing but **Vivid** — one orb of light on a black screen. No
landing page, no copy, no navigation. You tap the orb and it talks to you.

No build step and no dependencies.

```
index.html         the shell: a canvas, a button, six scripts
styles.css         the room the orb sits in
vivid-bridge.js    the seam between our pixels and the embedded widget
orb.js             the orb — everything that moves
memory.js          who it is talking to, kept in localStorage
tasks.js           background work the agent can start mid-conversation
task-worker.js     the Web Worker that actually does it
voice-session.js   ten minutes a session, unlimited sessions
```

## Run it

```bash
node .claude/serve.mjs
```

Then open http://localhost:4173.

The live widget key is **origin-locked**, so on localhost the real agent will
never connect. Add `?stub` for a local harness that reproduces the whole
contract — peer connection, data channel, tool calls, a stand-in voice — with
no network:

```
http://localhost:4173/?stub          drive the orb offline
http://localhost:4173/?stub&debug    ...and log what the bridge is doing
```

`?debug` works against the live widget too.

## How it works

The voice itself is the embedded widget from `platformvivid` — an OpenAI
Realtime client over WebRTC. It is a closed box: a closed shadow root, no
public API beyond `window.__vivid.run`, and its own small orb bottom-right.
We keep its transport and discard its pixels.

`vivid-bridge.js` is where that happens, and it **must load before
`widget.js`** — every patch has to be in place before the widget builds
anything:

| patched | for |
| --- | --- |
| `Element.attachShadow` | forces the widget's one root open, to read its status pill and click its canvas |
| `RTCPeerConnection` | the agent's audio track, and the `oai-events` data channel |
| `getUserMedia` | the microphone, for the level the orb moves on |

It exposes `Vivid.on('phase'|'level'|'event'|'open')`, `Vivid.tap()`,
`Vivid.send()` and `Vivid.onOutgoing()`. Everything else on the page is a
consumer of that and touches the network never.

## Memory

The agent's persona lives on the platform, keyed to the origin, so it cannot
be set from here. What `memory.js` does instead is amend the session once it
exists, in the second the widget leaves before its opening line:

1. reads the real config off `session.created`
2. sends `session.update` that **appends** to the platform's instructions and
   **merges** a `remember({name, note})` tool onto its existing tools — it
   never replaces either
3. replays what it kept last time as a system item, so the agent opens by name
4. holds the widget's `response.create` until all of that has landed, so the
   greeting is never generated by the un-amended session

When the agent calls `remember`, the widget dutifully posts it to a tool
endpoint that has never heard of it; the outgoing filter swaps the failure for
a real result before it reaches the model.

Everything is stored in `localStorage` under `vivid:memory`, on that device and
nowhere else — nothing is sent anywhere. `VividMemory.read()` and
`VividMemory.forget()` are there for a presentation reset.

## Background tasks

`tasks.js` gives the agent hands that keep working while it talks. It rides
the same two seams as memory:

1. once memory's amendment is acknowledged (`session.updated`), it merges a
   `run_task` tool onto the session's tools — never replacing anything
2. when the agent calls it, the work goes to a Web Worker
   (`task-worker.js`, off the main thread — the orb never drops a frame)
   and the tool answers `Started.` immediately, via the same outgoing
   rewrite that memory uses, so the conversation never stalls
3. when the worker finishes, the result waits for the gap after
   `response.done`, then lands as a system item followed by a
   `response.create` — the agent tells the user in its own words,
   mid-session, unprompted

Two tasks ship as demos: `timer` ("give me thirty seconds, then tell me")
and `nth_prime` (deliberately heavy, to show the work really is off-thread).
Adding one is a function in `task-worker.js` plus a line in the tool schema
in `tasks.js`. Tasks live and die with the session — hanging up drops
whatever was still running.

## Notes

- The character of the conversation is the `PERSONA` string at the top of
  `memory.js`. Edit the prose, not the plumbing.
- A session is ten minutes (`data-minutes` on the `voice-session.js` tag);
  there is no cap on how many. It is drawn as a thinning arc around the orb
  and never announced.
- `DESIGN.md` documents the design system of the marketing page this replaced.
  Nothing here follows it any more; it is kept for reference only.
